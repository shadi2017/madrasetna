# مدرستنا — إدارة الطلاب والحضور
تطبيق عربي من اليمين إلى اليسار يعمل من المتصفح على Android وiPhone والكمبيوتر.

## الحالة
- الواجهة وقاعدة البيانات والصلاحيات ووظيفة إدارة الحسابات مكتوبة، واختبارات محلية آلية مضافة.
- بدون إعداد Supabase تظهر **نسخة تجريبية مؤقتة** لا تحفظ أي بيانات حقيقية.
- تشغيل الحسابات والحفظ المشترك يحتاج إعداد مشروع Supabase ونشر وظيفة manage-student وفق SETUP.md.
- لم تُختبر الكاميرا أو المزامنة على أجهزة فعلية أو مشروع Supabase حي في هذه الجلسة.

## المميزات
- حساب أدمن بالبريد وكلمة المرور؛ حساب طالب باسم مستخدم وكلمة مرور.
- تسجيل ذاتي بموافقة الأدمن، وحالة انتظار/تفعيل/رفض، وحماية من التفعيل الذاتي.
- اسم وموبايل ورمز QR فريد لكل طالب، وتنزيل الرمز وتجديده ومشاركته كصورة عبر قائمة مشاركة الجهاز.
- حضور بالكاميرا للأدمن فقط، مرة واحدة لكل طالب ويوم.
- الطالب المفعل يقرأ بروفايله وحضوره وتقييماته فقط، مع حماية RLS داخل قاعدة البيانات.
- المجموع النهائي والترتيب لا يرجعهما الخادم للطالب قبل إعلان الأدمن. تعادل الدرجات يعطي نفس المركز.
- الحضور + 8 بنود يومية تُحوّل إلى 200، وأجزاء حفظ مستقلة إلى 200، والمسابقة إلى 200، والمشروع إلى 200. الإجمالي الافتراضي 800، والنهايات وعدد الأجزاء قابلة للتعديل.
- عدد أيام مفتوح وتواريخ يحددها الأدمن.
- اسم الدراسة والشعار والآية واللوجو قابلون للتعديل.
- حذف منطقي واسترجاع وسجل قبل/بعد، وإصدارات تمنع الكتابة فوق تعديل أحدث.
- Excel XLSX: تصدير كامل، قالب، معاينة وفحص قبل الاستيراد وتقرير لكل صف.
- Supabase Realtime، مع إعادة تحميل عند استعادة الاتصال وكل 30 ثانية.
- تصميم قابل للإضافة للشاشة الرئيسية؛ لا يحفظ بيانات الطلاب دون اتصال.

## تشغيل محلي
يتطلب Node.js 24.
```sh
npm ci
npm run dev
```
انسخ .env.example إلى .env.local وضع عنوان Supabase والمفتاح العام، ثم أعد تشغيل التطبيق.
```sh
npm test
npm run build
npm start
```

## التقنية
React + TypeScript + Vite، مكونات Radix/Shadcn، Supabase Auth/Postgres/Realtime/Edge Functions، html5-qrcode، qrcode، ExcelJS.
الواجهة Static وتُنشر على GitHub Pages أو Cloudflare Pages. كلمة مرور الخدمة لا تدخل في ملفات الواجهة مطلقًا.

## توزيع الملفات
- app/page.tsx: الشاشات والتنسيق بين عمليات التطبيق.
- app/features: النماذج والـQR والاستيراد.
- app/core: نموذج البيانات والاتصال والتحقق وExcel.
- supabase/migrations/001_initial.sql: مخطط النسخة الأولى.
- supabase/migrations/002_registration_grading.sql: التسجيل الذاتي والموافقة والمعادلة والترتيب وسياسات النتيجة.
- supabase/functions/manage-student/index.ts: إنشاء حساب الطالب وتغيير كلمة مروره، بعد التحقق من الأدمن.
- tests: اختبارات قاعدة البيانات والدرجات وExcel.
- .github/workflows/deploy.yml: بناء واختبار ونشر GitHub Pages.
- SETUP.md: خطوات التشغيل على الحسابات المجانية.

## حدود مهمة
الـQR يحتوي معرفًا عشوائيًا ولا يحتوي الاسم أو الموبايل. يمكن لأي كاميرا قراءة محتواه؛ قبول الحضور يتطلب حساب أدمن ودالة الخادم. مشاركة صورة QR لا يمكن منعها تقنيًا، لذلك الأدمن يطابق الاسم الظاهر مع الطالب.
الدرجات غير المسجلة تُحسب صفرًا، وكل يوم نشط محسوب ضمن المقام حتى لو تاريخه مفتوح أو مستقبلي. بند الموبايل «درجة الالتزام بالموبايل» وزيادة الدرجة تحسن المجموع.
Excel لا يغير هوية حساب موجود أو رمزه، ولا يستورد سجل التدقيق. سجلات محذوفة تُسترجع من التطبيق أولًا. استيراد بيانات جديدة إلى مشروع جديد يُنشئ حسابات ورموزًا جديدة، وليس نسخة من نظام تسجيل الدخول القديم.
